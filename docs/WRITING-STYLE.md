# 執筆マニュアル（Goûter版）

gouter.works のコラムを書くときのルール。ライターが書く場合もAIが書く場合も、同じ基準で判定する。

## この文書について

原典は「統一記法マニュアル（2020）Webライティングマニュアル vol.1」と「記事構成レクチャー」。
どちらもLiberarch発行、特定クライアント（医療法人あだち耳鼻咽喉科さま）仕様の個別版で、**複写・転用禁止**の資料。
原本はGoogleドライブのフォルダ「グーテコラム執筆」にある。

この文書は原典を書き写したものではなく、**Goûter名義の汎用版として実務ルールに組み直したもの**。
執筆代行を商品にする以上、クライアント個別版のままでは他社に渡せないため。

原典から意図的に変えた点は「2026年時点での改訂」に明記している。**それ以外の中核ルールは原典のまま**。
構成手順、PREP法、MECE、1記事1テーマ、タイトルの前後半構成、最初のH2、まとめの書き方、分量目安、
チェックリスト——これらは古くなっていない。AIが整った文章を無限に出せるようになったぶん、
「検索意図に最初から答える構造か」「1記事1テーマで散らかっていないか」「まとめが感想で終わっていないか」
の価値はむしろ上がっている。**執筆代行の売り物は、この構造ルールそのもの**。

---

## 1. 執筆手順

1. テーマを決める（`docs/THEME-BACKLOG.md` の公開順に従う）
2. KWを2〜3語で選ぶ
3. **SERPを実際に見て、顕在ニーズ／潜在ニーズを確定する**
4. タイトルと見出しを決める
5. 執筆
6. 推敲・校閲
7. 装飾
8. アイキャッチ作成
9. 下書きで反映 → レビュー → 予約投稿

3を机上で埋めない。上位1〜10位を実際に読み、何を知りたい人が検索しているのかを見てから構成を決める。
上位記事の良い部分は取り入れ、弱い部分で上回る。

## 2. キーワード

- 2語または3語の組み合わせ（ロングテール）
- 検索ボリュームは100〜1000程度を狙う。サイト評価が上がってきたら1000以上へ
- CPCが高いKWはコンバージョンに近いが競合も強い。狙うかは記事ごとに判断

**KWの密度は追わない。** 自然に含まれていればよく、詰め込みは逆効果になる。

## 3. タイトル

**本文より何より、タイトルが一番大事。** 何度でも書き直す。

- **32文字以内**
- **前半16字＋後半16字の2部構成**、区切りは `！` か `？`
  - 前半 … 最も強調したい感情＋話題になるワード
  - 後半 … 誰に向けた記事かを明示（何に興味がある人か、何に困っている人か）
- 狙うKWは**完全一致**で、**できるだけ先頭に**、最低1回・最大2回
- 2回入れるときは距離を空ける
- 単語の羅列にしない。助詞・助動詞を必ず使う
- **修飾語ではなく主語として**入れる
  - ✗ 自分にあったスタイルで「資格取得」をめざす
  - ○ 「資格取得」は受験日を決めるのが鍵！
- 英数字は半角

分割した記事でも `【前編】` のような記号は付けない。32字をKWに使いたいため。

### 読まれるタイトルの条件

誰に向けた記事かひと目でわかる／内容がイメージできる／具体的な数字が入っている／
キラーワードが入っている／簡単だとわかる／現実的な成果が伝わる／情報量が伝わる／
必要性・緊急性がある／聞き慣れないワードで関心を引く／役に立つと感じられる。

全部を詰め込む必要はない。組み合わせた結果、ひと目で「自分の役に立つ」と感じられるかで判断する。

## 4. 見出し

- 見出しに狙うKWを含める
- **最初のH2は、タイトル前半と同じ意味・同じKWを含むものにする**
- H2の数は分量に応じる。3,000字なら**まとめを含めて4本まで**、5,000字なら5〜6本
- **既定は「まとめを含めて4本」。** 3,500字で通るので、書き足しの往復が起きない。
  5本立てると4,000字必要になり、書いたあとに膨らませる作業が発生する。
  5本にするのは、4本では収まらない内容があるときだけ
- **MECE** — もれなく、ダブりなく。ただし範囲を広げすぎない。タイトルと見出しから連想できない内容を本文に入れない

最初のH2のルールは「H2にKWが入るから効く」のではない。
**書き手に、検索意図への答えを最初のセクションで出させるため**にある。
回りくどい前置きから入る記事を構造的に禁止する仕掛けなので、ゆるめない。
機械的に当てはめて日本語が不自然になる場合だけ、同じ意味・同じKWを含む形に寄せればよい。

## 5. 本文

**構成はPREP法に統一する。**

```
タイトル
アイキャッチ
リード文（Point：要点）
目次（自動）
H2（Reason：理由）
  H3
H2（Example：具体例）
H2 まとめ（Point）
```

- **1記事1テーマ**。散らかしたぶんだけ評価が下がる
- リード文は「読みたかったのはこれだ」と思わせる文章。ここにもKWを含める
- **ベイビーステップを示す** — 今すぐできる第一歩を書く。「これぐらい言わなくてもわかるだろう」で省略しない
- **まとめは感想で終わらせない**。冒頭の結論を再度書き、各見出しを振り返り、伝えたかったことを短くまとめる
- ベネフィット（読者が得られる結果）を伝える。メリットの説明で止めない

## 6. 分量

| 項目 | 基準 |
|---|---|
| 本文 | **3,500〜5,500字**（原典の上限は6,000字） |
| 各見出し | 300字前後（H3を含めた1ブロックあたり） |
| 1行 | 40字程度 |
| 段落ブロック | 3〜4行まで |

**5,500字を超えそうなら分割する。** 分割の作法は `docs/THEME-BACKLOG.md` を見る。

## 7. 一次情報（必須）

**1記事につき最低1つ、次のいずれかを入れる。**

- 具体の数字（実際に測った値、実際の料金、実際の件数）
- 現場で見たこと（クライアントワークで起きたこと、店舗で観察したこと）
- 失敗（うまくいかなかった例と、その理由）

これが入っていない記事は一般論の量産物と区別がつかず、AIが無限に生産する側と同じ土俵に乗る。
量で押す戦略を取るときほど、この条件が効く。**入っていない原稿は公開しない。**

なお、**実績の捏造は禁止**。「クライアントで◯%改善した」は、実際にその数字があるときだけ書く。
書けるエピソードが無い場合は、記事を出す前に確認する。

## 8. 出典・ファクトチェック

- 統計・法令・料金・制度を書くときは、**出典と取得日を明記する**
- 一次ソース（公的機関、公式ドキュメント）に当たる。まとめ記事を出典にしない
- 期間限定の情報は、**終了日を過ぎていないか確認してから書く**
- 未確認の固有名詞・日付・営業情報を断定しない

執筆代行で最も事故が起きるのがここ。

## 9. AIの使い方

- AI生成をそのまま納品しない
- 事実確認の責任は執筆者にある。AIが書いた数字・固有名詞は必ず裏を取る
- **一次情報（§7）は必ず人が足す**
- AIが書いた原稿をリライトするときは、一般論の骨格をそのまま残さない

## 10. YMYL

お金・経営・契約の話は一部YMYLにかかる。

- 断定を避ける（「必ず儲かる」「絶対に節税できる」は書かない）
- 個別事情で結論が変わることを明記する
- 士業の領域（税務・法務の個別判断）に踏み込まない

## 11. 画像

- alt属性は必須。日本語で内容を書く
- 横幅1200px以上
- アイキャッチの文字組みは3行構成
- 素材の権利関係を確認したものだけを使う。台帳は `docs/EYECATCH-ASSETS.md`

## 12. 内部リンク

- 1記事につき、関連する既存記事へ最低1本
- 派生元の記事には必ず張る（`docs/THEME-BACKLOG.md` の「派生元」列）
- 分割した記事は相互に張る（前編末尾→後編、後編冒頭→前編）
- アンカーテキストはリンク先のKWを含む自然な日本語にする

## 13. 装飾

**未決定。** 原典の装飾ルール（`concept-box6`、`[box03]`、`box21` など）は旧JINのもので、
現行のJIN:Rでは動かない。いまのコラムはインラインstyleの独自ボックスで組まれていて、
統一記法から外れている。

**放置すると記事ごとに見た目がばらつく。** 早めに決めること。→ `docs/HANDOFF.md`

## 14. 成果指標

**問い合わせ数で測る。** gouter.works はオウンドメディアであり、目的は問い合わせ獲得。

原典にあったGoogleアドセンス運用・PV×クリック率での評価・ライターへのインセンティブ配当は、
**このサイトでは使わない**（広告収益が目的ではないため）。

検索順位とPVは、リライト判断のための材料として見る。サーチコンソールのコネクタは提供されていないので、
必要なときは管理画面からCSVをエクスポートして読む。月1回で足りる。

## 15. 公開前チェックリスト

`■` は機械判定できる項目（`tools/wp.py lint` が見る）。

- ■ タイトルが32字以内
- ■ タイトルに `！` か `？` の区切りがある
- ■ タイトルにKWが完全一致で入っている
- ■ タイトルの前方にKWがある
- ■ 最初のH2にKWが入っている
- ■ 本文が3,500〜5,500字
- ■ H2の数が分量に見合っている
- ■ 最後のH2がまとめ
- ■ 内部リンクが1本以上ある
- □ タイトルと記事内容、見出しと本文が一致している
- □ 一次情報が最低1つ入っている（§7）
- □ 出典と取得日が書かれている（§8）
- □ 誤字脱字がない
- □ 専門用語・難しい言い回しを避けている
- □ altが全画像に入っている

校閲・推敲には文賢を使う。コピペチェックはCopyContentDetector。

### 背景

2020年以降に起きて、原典に反映されていない変化。

- 2022年12月、E-A-Tに **Experience（経験）** が加わりE-E-A-Tになった
- 「検索エンジンのために作られたコンテンツ」を減点する仕組みが入り、その後コア評価に統合された
- **AI Overviews** の登場で、検索結果上で答えが完結してクリックされないKWが増えた

ロングテールでKWを埋めるだけの記事は当時より通用しにくい。戦略自体は有効だが、
**一次情報が入っていない記事は勝てない**という前提条件が付く。だから§7を必須にしている。

## 17. 版管理

この文書はgitで管理する。原典が想定していた「更新したページだけ印刷して送付」の運用はしない。
変更するときはコミットに理由を書く。

## 18. 原稿の置き場所

`docs/articles/<公開順の番号>-<slug>.md` に置く。Markdownで、先頭にフロントマターを付ける。

```
---
title: 口コミ返信の例文つき！低評価レビューで店の印象を落とさない書き方
kw: 口コミ 返信 例文
primary: 飲食店クライアントで返信開始から3か月の口コミ件数を実測
post_id: 9327
---
```

`primary` は§7の一次情報。何を入れたかを一行で書く。**空だとlintが通らない。**

```
python3 tools/wp.py lint docs/articles/01-kuchikomi-henshin.md
python3 tools/wp.py push docs/articles/01-kuchikomi-henshin.md
python3 tools/wp.py schedule docs/articles/01-kuchikomi-henshin.md --at 2026-09-01T07:00:00
```

`push` と `schedule` はlintを通ってからでないと実行されない。
