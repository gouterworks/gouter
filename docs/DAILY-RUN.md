# 毎日の運転手順

これは**人がいない状態で回すための手順書**。定期実行がこの通りに動く。
新しいセッションから始める場合も、これだけ読めば足りる。

## 前提

- 作業ブランチは `claude/article-creation-67nzgw`
- **WordPressへの操作は、このセッションからは届かない**（`gouter.works` がegressで遮断される）。
  すべて GitHub Actions のランナー経由で行う（`tools/pending.json` を置いてpushする）
- 認証情報はGitHubのシークレット（`WP_URL` `WP_USER` `WP_APP_PASSWORD`）にある。値を見る必要はない

## 1日の流れ

### 1. 枠の空きを見る

```json
[["slots", "--count", "6"]]
```

`tools/pending.json` に置いてpushすると、ランナーが実行してログに出す。
複数のコマンドを並べれば、1回でまとめて実行される。

**pushだけでは起動しないことがある。** 2026-08-26 に、pushしてもワークフローが
走らない状態が発生した（原因は不明）。**pushしたあとに手動起動をかける**のが確実。

```
mcp__github__actions_run_trigger  method=run_workflow
  workflow_id=column.yml  ref=claude/article-creation-67nzgw
```
枠は日本時間の **07:00 / 12:00 / 19:00**。埋まっている枠は飛ばして次の空きが出る。

### 2. 次に書くテーマを決める

`docs/THEME-BACKLOG.md` の公開順の表で、状態が空欄のいちばん上から取る。

**同じジャンル・同じ商材を2本続けない。** 表の並びを守っていれば自然にそうなる。

### 3. 書く

`docs/WRITING-STYLE.md` に全部書いてある。特に外せないのは次の3つ。

- **書く直前にSERPを実際に見る。** 顕在ニーズと潜在ニーズを確定してから構成を決める
- **一次情報を最低1つ。** 具体の数字、現場で見たこと、失敗のどれか
- **実績を捏造しない。** 「クライアントで◯%改善」は実際の数字があるときだけ。
  書けるものが無ければ、公開情報の実数や、読者が自分の数字で追える計算に置き換える

原稿は `docs/articles/<公開順の番号>-<slug>.md`。フロントマターの `primary` に、
一次情報として何を入れたかを一行で書く。空だとlintが落ちる。

書けたら手元で確認する。ここはネットが要らない。

```
python3 tools/wp.py lint docs/articles/04-xxx.md
```

### 4. 下書きとしてWordPressへ入れる

```json
[["push", "docs/articles/04-xxx.md"]]
```

ログに出た記事IDを、フロントマターの `post_id` に書き足す。

### 5. アイキャッチを作る

**母艦（`DAF2Hmjvfm4`）は編集しない。** 直近の作業用デザインを `copy-design` で複製して使う。
まっさらなページにテキストを足すとフォントが変わり、コネクタからは直せない。詳細は
`docs/EYECATCH-ASSETS.md`。

背景写真は**過去記事と重複させない**。母艦の60ページは過去記事のアイキャッチそのものなので、
そこから抜いた写真は使わない。Pexelsなどの無料ライセンス素材を `upload-asset-from-url` で
取り込む。使ったものは台帳に追記する。

文字は3行構成。上＝記事の要点、中央＝主題、下＝対象や切り口。

できたら `export-design` でPNGにする。

### 6. 反映して予約する

```json
[
  ["featured", "--post", "9999", "--url", "<書き出したPNGのURL>", "--alt", "<日本語のalt>", "--name", "9999-slug.png"],
  ["audit", "--post", "9999", "--kw", "<狙ったKW>"],
  ["schedule", "docs/articles/04-xxx.md", "--next"]
]
```

`audit` が落ちたらそこで止まる。**違反したまま予約されることはない。**
落ちた理由がH2の本数なら、`demote` で見出しの階層を1つ下げれば直ることが多い。

### 7. 後片付け

- `tools/pending.json` を消す
- `docs/THEME-BACKLOG.md` の状態欄を更新する
- `docs/EYECATCH-ASSETS.md` に使った写真を追記する
- コミットしてpushする

## テーマが減ってきたら

**残りが6本を切ったら補充する。** 1日3本なら2日分しかない。

補充のやり方は `docs/THEME-BACKLOG.md` の作り方に従う。既存記事の隣に置く、
ジャンルが連続しない並びにする、タイトルはマニュアル準拠、の3点を守る。

## 止めるとき

次のどれかに当たったら、**予約せずに人に聞く**。

- 一次情報がどうしても用意できない
- 事実確認が取れない数字や制度を書く必要がある
- `audit` が2回直しても通らない
- テーマの補充で、既存記事と重複しない切り口が見つからない

## 反映のあとに見るもの

`python3 tools/wp.py queue` を待ち行列の最後に入れる。

- **予約**が公開される順に並ぶ。IDが前後していたら、どこかで順番が崩れている
- **下書き**が別に出る。ここに同じタイトルが2つ並んでいたら重複。`trash --post` でゴミ箱へ

`slots` は枠の空きしか見ない。**下書きの溜まりは queue でないと見えない。**

## 予約が出ていないとき

`queue` の予約の先頭が、今日より前の日付になっていたら止まっている。

```
python3 tools/wp.py overdue          # 遅れているものを見る
python3 tools/wp.py overdue --apply  # 公開する
```

`wpcron.yml` が毎回これを走らせるので、通常は手で打つ必要はない。
**GitHubの定期実行が落ちた日は拾えない**ので、そのときだけ手で回す。
