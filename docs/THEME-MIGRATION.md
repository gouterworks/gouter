# JIN:R から STREETIST へ

## 決めたこと

| | |
|---|---|
| 新しい親テーマ | **STREETIST**（フォルダ名 `streetist`、小文字） |
| トップページ | **LP風のまま**。記事ベース（LIG風）にはしない |
| 作り方 | **`get_header()` を使うテンプレートを書く**（案B） |
| 自分で書くページ | トップと Service の2枚だけ |
| 記事・一覧・その他の固定ページ | **STREETIST標準**に戻す |

トップをLP風のまま残すのは、成果指標が問い合わせ数だから。記事一覧が主役の形は
「読む人」を増やす設計で、「相談する人」を増やす設計ではない。
記事から入ってきた人はトップを踏まないので、そこは記事ページ側のCTAで受ける。

## 進め方

**新しいテーマを別フォルダに置いて、並行させる。** 公開サイトには触らない。

```
themes/gouter      ← 今のもの。JIN:Rの子。最後まで触らない
themes/gouter-st   ← 新しいもの。STREETISTの子。ここで作る
```

リポジトリでは `gouter-st/` 以下が新テーマ。Actions の
**Deploy theme (STREETIST版)**（`.github/workflows/deploy-st.yml`）を
Run workflow で流すとサーバーに置かれる。

このワークフローは `workflow_dispatch` だけで、pushでは動かない。
**流してもサーバーにフォルダが1つ増えるだけで、公開サイトは変わらない。**

確認は 外観 → テーマ → Goûter (STREETIST) の **ライブプレビュー**。
納得できたら「有効化」。それが切り替えの瞬間になる。

**問題が出たら、管理画面でテーマを Goûter に戻すだけで完全復旧する。**
旧テーマがフォルダごと残っているため。

STREETIST に返すぶんと、JIN:R を打ち消すためだけに書いたぶんが消えるため。

## 404.php をどうするか（判断が要る）

移行の方針を決めたあとに `404.php` が追加された（8/29「404を行き止まりにしない」）。
これも `get_header()` を呼ばず、自前で `<html>` から書き、JIN:R の打ち消しCSSを
持っている。**front-page.php と同じ直しが要る5枚目のテンプレート。**

方針（記事・一覧・その他は STREETIST 標準）に素直に従うなら 404 もテーマに返す。
ただし「行き止まりにしない」ための検索窓と導線は作ったばかりで、STREETIST の
標準404がそこまでやるとは限らない。**どちらにするか決める。**

- テーマに返す → `404.php` と `style.css:663-684` を捨てる
- 持っていく → `get_header()` 版に書き直す（front-page.php と同じ作業）

## 守るルール

JIN:R のときは、テンプレートが親テーマと殴り合っていた。同じことを繰り返さない。

1. **`get_header()` `get_footer()` を必ず使う。** 自前で `<html>` から書かない
2. **テーマのIDやクラスを打ち消さない。** `#wrapper` `#main` を1つでも書いたら負け
3. **`!important` を書かない**
4. **折り返し幅はテーマに合わせる。** 旧テーマは 700 / 767 / 900 / 999px が
   バラバラに使われていた
5. **サイドバーの有無はテーマの設定で決める。** CSSで消さない

旧テーマで実際に書かれていた、やってはいけない例（`front-page.php:78-88` ほか）:

```css
/* 親テーマ（JIN:R）のレイアウト制約を打ち消す */
#wrapper, #contents, #main, .main-inner, .content-inner {
  max-width: none; width: auto; margin: 0; padding: 0; float: none;
}
body { padding-top: 0 !important; }
```

これが `front-page.php` `archive.php` `page-gt.php` の3枚に入っていた。
**新テーマには持ってこない。**

## 落とし穴

**転送は上書きだけで、削除は伝わらない。**
`scp-action` はコピーしかしないので、リポジトリからファイルを消しても
サーバーには残り続ける。「消したはずのテンプレートがまだ効いている」という
一番わかりにくい状態になる。フォルダを分けているのはこれを避けるためでもある。

**旧テーマの `style.css` の `Template:` を書き換えてはいけない。**
`gouter` フォルダは公開サイトそのもの。ここの親テーマ指定を書き換えて main に
push すると、プレビューを経由せずに本番がSTREETISTの子に変わる。
しかもJIN:R打ち消しCSSが残ったままの状態で。

**旧テーマの `single.php:148` は `get_template_part('ad-finish')` を呼んでいる。**
これは JIN:R の親テーマにあるファイル。新テーマには持ってこない。

**AdSense はテーマ由来ではない。**
STREETIST のプレビューでもトップに広告が出ていた。テーマを替えても残る。
問い合わせ数が指標なら、トップの広告は外す判断をしたほうがいい。
