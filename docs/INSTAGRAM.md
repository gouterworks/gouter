# インスタグラム運用

[@gouter.works](https://www.instagram.com/gouter.works/) の運用ルール。**記事の運用（`DAILY-RUN.md`）とは目的も指標も別**にする。

## 決めたこと

| | |
|---|---|
| 目的 | **相談の入口**。集客・HP更新・SNS活用の相談を受けたい。特定の商品を売るためではない |
| 誰に | **全国の事業主。一次産業から六次産業まで、ジャンルは問わない** |
| 束ね方 | 業種で括らない。**「作る人が、売る側に回ったときに詰まること」**で括る |
| 指標 | **DMとプロフィールアクセス**。保存数は補助。**サイト流入では測らない** |
| 本数 | **週2本**。毎日にしない |
| 形式 | **カルーセル7〜9枚**。アイキャッチ1枚の転載はしない |
| 何を出すか | 集客・HP・SNSを**横断させる**。ただし**一般論の解説は出さない**（下の基準） |
| 書き方の禁則 | **業種名を主語にしない。** 「飲食店の場合」で書くと、農家が自分ごとにしない |
| 導線 | **DMで受ける。** 問い合わせフォームに送らない |
| 記事との繋ぎ方 | **記事を書いたときに、フロントマターの `ig` で判定する。** `wp.py ig` が8枚に割る |
| 自動化 | **最初の8本は手で出す。** そのあと数字を見て決める |

## 目的 — 相談を受けるため

**SNS運用代行の受注が目的ではない。** それはGoûterの商品の1つでしかない。

受けたいのは、集客・HP更新・SNS活用まわりの**相談そのもの**。何が要るかは相談してから決まる。
`front-page.php` に書いてある「いきなり手段の話はしません。その事業がどうなればいいのかを先に決めます」
がそのまま当てはまる。

この目的から、投稿の設計が3つ決まる。

1. **ジャンルを1つに絞らない。** 集客の話、HPの話、SNSの話が並んでいることそのものが
   「この人にはいろいろ聞ける」という判断材料になる。1ジャンルに寄せると、その専門家に見えて
   相談の幅が狭まる
2. **相談は「この人なら知ってそう」で来る。** 情報をまとめた投稿ではなく、**実際にやった人にしか
   書けないもの**を出す。一般論の解説は、出すと逆に「情報発信の人」になって相談が来ない
3. **完結させない。** 全部答えてしまうと相談する理由が消える。**判断の分かれ目まで出して、
   「どっちを取るかは状況による」で止める**のが、いちばん相談につながる

## 誰に向けるか

**全国の事業主。一次産業から六次産業まで、ジャンルは問わない。**

ここで正直に書いておく。**「ジャンル問わず」は、インスタではいちばん届きにくい設定**になる。
興味関心で配られる仕組みなので、投稿のジャンルが散っていると「誰向けのアカウントか」が
判定されず、伸びない。かといって業種で絞ると相談の幅が狭まる。目的に反する。

**抜け道は、業種ではなく「状況」で括ること。**

> **作っている人が、自分で売る側に回ったときに詰まること。**

六次産業化はこの状況そのもの（作る人が、加工して、売るところまでやる）。
飲食店も、小売も、制作業も、突き詰めると同じ状況にいる。
**業種を問わないまま一貫性が出て、アルゴリズムにも乗る。** これを軸にする。

だから書き方に禁則が1つ増える。**業種名を主語にしない。**

| ✗ | ○ |
|---|---|
| 飲食店のPOPの書き方 | 売り場で、説明しないと伝わらない商品があるとき |
| 農家がインスタで直販するには | 作った本人が売ると、値段の話がしにくくなる |
| 士業のホームページに必要な項目 | 会ったことのない人に、頼んでいいかを判断させるページ |

状況で書けば、読んだ人が自分の業種に翻訳する。**翻訳させたほうが、相談が来る。**

地域（宗像・福岡）は**プロフィールに置くだけ**にする。「どこの誰か」は信頼の材料になるが、
**投稿のハッシュタグを地域で絞らない。** 全国が相手なので、絞ると届く範囲を自分で狭めることになる。

## なぜ止まったままにしないのか

止まっているアカウントは、**相談していいかどうかの判断材料にならない**。
「この人なら知ってそう」と思われる場所が、いま空白になっている。

   **相談はDMで受ける**

## 何を出すか

**集客・HP更新・SNS活用の3つを横断させる。** 週2本なら、2本を別ジャンルにする。

選ぶ基準は、ジャンルではなく**中身**で決める。

| 出す | 出さない |
|---|---|
| 現場で見たこと・やって失敗したこと | 一般論の解説 |
| 判断の分かれ目（AとBのどちらを取るか） | 手順の全部入り |
| 配布物・テンプレートが付く回 | 用語の説明 |

`THEME-BACKLOG.md` が出した診断——**一般論が効かない、配布物・実務・現場が効く**——は
インスタでも同じに扱う。理由が同じだからではなく、**相談は実務を知っている人にしか来ない**から。

### 記事の運用に繋ぐ

記事は毎日1本、`DAILY-RUN.md` の手順で回っている。**インスタはその中に組み込む。別立てにしない。**

繋ぎ目はフロントマターの `ig` 1つ。

```yaml
ig: yes                      # カルーセルにする
ig: no: 一般論の解説回        # しない。理由を書く
ig_url: https://www.instagram.com/p/xxxx/   # 投稿したら書き足す
```

**判定は記事を書いた直後にやる**（`DAILY-RUN.md` の手順3）。後から選ぼうとすると、
そのとき60本を読み直すことになる。週2本なので、**その週にすでに2本 `yes` があれば `no`**。

`lint` は `ig` が無いと警告を出す（エラーにはしない。既存記事が全部落ちるため）。

出す回が溜まっているかは、これで見る。

```
python3 tools/wp.py ig --pending
```

`ig: yes` で `ig_url` が空のものが並ぶ。**待ち行列の考え方は記事の `queue` と同じ。**

記事に無い材料（クライアントワーク、ツキヌケの編集現場）から直接作ってもいい。
そのときは原稿を書かずにカルーセルだけ作る。**繋ぐのが既定で、外れるのは例外。**

## 割り方

執筆マニュアルの決めごとが、そのままカルーセルの構造になる。**だから機械で割れる。**

```
python3 tools/wp.py ig docs/articles/38-neage-tsutaekata.md
```

| 枚 | 中身 | 出どころ |
|---|---|---|
| 1 | 表紙 | **タイトルの前半16字**。`！` `？` で切ってあるので、そのまま表紙のコピーになる |
| 2 | 結論 | PREP法の P。リード直後にある |
| 3〜6 | 本文 | **H2ごとに1枚。** H2は3,000字で4本までと決めてあるので、素直に割れる |
| 7 | 一次情報 | **ここだけ手で書く。** `primary` は書き手向けのメモで、読者に見せる文ではない。材料として併記される |
| 8 | 導線 | **「同じことで困っていたらDMで聞いてください」。** サイトへ送らない |

3〜6枚目は**各節の最初の太字**を拾う（PREP法で結論が先に来るため）。
2枚目だけは**リードの最後の太字**を拾う（リードは問題提起→結論の順で書くため）。
記事の書き方が決まっているから、この拾い方が成立する。

出てきた文言はそのまま使わず、**業種名が主語になっていないかだけ見て直す**。

7枚目が要。**ここが「相談していい人か」の判断材料になる。**
`primary` が薄い記事は、そもそも `ig: no` にする。

記事のルールはそのまま持ち込む。**実績を捏造しない。** 「クライアントで◯%改善」は実際の数字があるときだけ。

## キャプション

- **インスタの中で完結させる。** 「続きはブログで」を主目的にしない。リンクは踏まれない前提で設計する
- 記事の要約ではなく、**カルーセルで言い足りなかった1つ**を書く
- **最後は問いで終える。** 「うちはどうだろう」と思った人がDMを送る理由になる
- 最大2,200字。使い切らない
- ハッシュタグは**5〜10**。30個並べない。**地域では絞らない**（全国が相手）。
  テーマと、読んだ人が自分を重ねる状況の言葉で付ける

## 出す時間

**相手の生活時間が1つに定まらない。** 農家・漁師は朝が早くて夜が早い。店をやっている人は
夜が遅い。**20時に揃えると、片方に届かない。**

だから週2本を**別々の時間に出して、比べる**。

| | 曜日 | 時間 | 狙い |
|---|---|---|---|
| 1本目 | 火 | **6:30** | 朝が早い側。作業前に見る時間 |
| 2本目 | 金 | **20:00** | 夜が遅い側。店が落ち着く時間 |

**どちらも根拠のある数字ではない。** 8本（4週間）出して、伸びたほうに寄せる。
比べるために、**2本の中身のジャンルは近いものにしない**（時間の差か中身の差か分からなくなる）。

記事の枠（朝7:00）とは重ねない。同じ時間に同じ内容が2か所から出ても意味がない。

## 作り方

`DAILY-RUN.md` の手順7がこれ。記事を書く流れの中に入っている。

1. `python3 tools/wp.py ig <原稿>` で割り付けを出す
2. **7枚目（一次情報）を手で書く。** 材料として `primary` が併記される
3. 各枚の文言を、**業種名が主語になっていないか**だけ見て直す
4. Canvaで画像を作る（下の手順）
5. 投稿する。**最初の8本は手で出す**
6. フロントマターに `ig_url` を書き足す

### Canvaでの作り方

1枚目を作ったときの手順。**フォントを壊さない道はこれしかない**ので、この順で踏む。

1. **母艦（`DAF2Hmjvfm4`）から8ページを `copy-design` で複製する。** 母艦は編集しない。
   新しいページを足すのではなく複製なのは、**正しいフォントが複製でしか入らない**ため
2. `resize-design` で **1080×1350（4:5）** にする。フォントは保たれるが、**レイアウトは崩れる**（前提）
3. 各ページに**紺一色（`#16233C`）の矩形を全面に敷いて、母艦の背景写真を隠す。**
   母艦の写真は過去記事のアイキャッチそのものなので、そのまま使うと**8枚全部が過去記事と重複する**
4. テキストを `layer_element` で前面に出し、**小さい要素だけ**を使って組む。
   大きい表示用の要素は差し替えるとフォントが飛ぶので `delete_element` で消す
   （条件は `EYECATCH-ASSETS.md`）
5. **改行と、日本語フォントに無い記号（`→` など）を入れない。** 入れた時点でフォントが飛ぶ
6. コミットする前に、**`document` の `fontRef` が全要素 `YADK30shh-I` か目で確かめる。**
   サムネイルでは気づけない。壊れていたら `cancel` してやり直す
7. `export-design` で **JPEG** にする。アイキャッチ（PNG）とは形式が違う

**文字は1枚10字まで。** 1枚1メッセージにすると、そのまま収まる。

背景写真を使う回は、**過去記事のアイキャッチと重複させない**。使ったものは `EYECATCH-ASSETS.md` に追記する。

## 自動化 — 8本出してから決める

技術的には最後までつながることを確認済み（2026-09-09）。

- Windsor の Instagram コネクタに `create_carousel_post` がある。
  **2〜10枚、JPEG、8MB以下、アスペクト比4:5〜1.91:1、公開URL、キャプション2,200字まで**
- 画像の公開URLは、WordPressのメディアがそのまま使える（`wp.py featured` が既に画像を上げている）
- つまり **Canva → 書き出し → WPメディア → カルーセル投稿** で全部自動化できる
- 文言側はもう繋がっている。`wp.py ig --json` が、投稿に渡す形で8枚ぶんを出す。
  **残っているのは画像を作るところだけ**

**ただし、いまWindsorにつながっているのは Google Ads / GA4 / Search Console だけ。
Instagram は未接続。** 自動化するなら、まずビジネスアカウントを接続する。

自動化から入らない理由は、記事の運用で一度やったことと同じ。
**効かないものを自動で量産することになる。** 8本＝4週間ぶんの数字を見てから決める。

そして**投稿を自動化しても、DMの返信は自動化しない。** 相談の入口が目的である以上、
そこが人でなければ意味がない。**自動化の対象は投稿までで、返信は含めない。**

`HANDOFF.md` の6番にある Blog2Social はここでは使わない。**あれはアイキャッチ1枚の自動転載で、
カルーセルを作れない。** 手数はゼロになるが、いちばん伸びない形になる。

## 未確認

このセッションからは gouter.works にも instagram.com にも到達できない（egressで遮断）。
**アカウントそのものを見て決めたことは1つも無い。** 次の点は人が見て埋める。

- 最後の投稿がいつか。フォロワー数
- これまでの投稿の形式（カルーセルの実績があるか）
- **プロフィール文が「相談していい人」に見えるか。** 投稿より先にここが読まれる。
  全国・ジャンル問わずが相手なので、**業種を書かず、状況で書く**
- プロフィールのリンク先
- ビジネスアカウントかどうか（`create_carousel_post` はビジネス／クリエイターアカウントが要る）

## ついでに気づいたこと

**Direct が404で、全体の51%を占めている。** サイトの規模に対して多すぎる。
自分と関係者のアクセスが混ざっているか、計測から漏れている経路がある。
**ここが片付かないと、どの数字も割り引いて読むことになる。** 別途見たほうがいい。
